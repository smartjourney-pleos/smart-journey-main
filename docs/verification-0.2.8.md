# 앱 0.2.8 확인 기록 (2026-11-12)

대상: 앱 0.2.8(versionCode 10), 소스 태그 `v0.2.8-submission1`. 환경은 Pleos Connect Emulator v2.1.0(Android Automotive, API 34, 운전자 사용자). 시연용 데이터이며 실제 매장에는 접수되지 않습니다.

## 빌드

- `./gradlew :app:assembleDebug :app:assembleRelease :app:testDebugUnitTest :app:lintDebug` 성공.
- 단위 테스트 84개 통과, lint 오류 0건(경고 37건은 기존과 동일).
- release APK는 릴리스 키로 서명했고(apksigner verify 통과) 데모 도구(DemoReceiver, ProbeActivity)를 포함하지 않습니다.

## 순정 내비 "안내 종료" 처리 (에뮬레이터 실기 확인)

| 상황 | 결과 |
| --- | --- |
| 접수 전 방문 중 내비 안내 종료 | 방문이 닫히고 홈이 방문 계획 화면으로 돌아옴 (3회 확인) |
| 접수 확정 후 내비 안내 종료 | 방문·접수 유지, "이미 접수한 웨이팅은 유지돼요" 알림 |
| 방문 현황의 "방문 끝내기"(접수 확정) | 확인창 "계속 안내" / "안내 종료". 계속 안내는 유지, 안내 종료는 방문 추적만 끝내며 접수는 그대로 |
| 접수 중·결과 미상 | 미접수로 단정하지 않고 유지 (복원 상태를 쓴 단위 테스트로만 확인) |

- Pleos NaviHelper 공개 SDK에는 내비의 "안내 종료"를 누르기 **전에** 알려 주는 이벤트가 없습니다. `onRouteCancelled`는 이미 종료된 뒤의 알림이므로, 종료 전 확인은 앱의 "방문 끝내기" 버튼에서만 보장합니다. 내비 경로는 자동 복구하지 않습니다.
- 우리 앱이 경로를 요청하는 중이거나 직후 3초 안에 오는 취소 이벤트는 운전자 조작으로 보지 않습니다. 경로 재요청 때 취소 이벤트가 0.2초 뒤 도착하는 것을 확인했습니다.
- 매장 웨이팅은 사용자 승인 없이 취소하지 않습니다.

## 지도 위 질문 카드

권한을 허용한 환경에서는 10초 카운트다운 카드가 표시됩니다. 설치만 한 일반 경로에서는 다음 이유로 표시할 수 없었습니다(권한 부여 없이 확인).

- "다른 앱 위 표시" 권한 설정 화면(`ACTION_MANAGE_OVERLAY_PERMISSION`)을 받는 앱이 이미지에 없습니다.
- 백그라운드에서 Activity를 시작하면 `BAL_BLOCK`으로 거절됩니다.
- fullScreenIntent 알림은 등록되지만 Activity가 실행되지 않습니다.
- 차량 알림 주입기가 특권·플랫폼 서명 앱이 아닌 앱의 알림을 배너로 표시하지 않습니다.

따라서 기본 경로는 음성 질문이며, 지도 위 카드는 권한이 있는 환경의 선택 기능입니다.
